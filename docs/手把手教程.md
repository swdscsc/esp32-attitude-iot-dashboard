# 手把手教程：从烧录到出分析报告

> 前提：你的电脑已装好 ESP-IDF（之前 attitude-monitor 实训用的那套环境就行），
> 手上有 ESP32-S3 + QMI8658 的板子。全程约 40 分钟。

## 第 1 步：填 WiFi 密码（2 分钟）

```bash
cd esp32-attitude-iot-dashboard
cp components/WIFI/wifi_secrets_example.h components/WIFI/wifi_secrets.h
```

打开 `wifi_secrets.h`，把 `YOUR_WIFI_SSID` / `YOUR_WIFI_PASS` 换成手机热点或家里 WiFi。
**这个文件不会被 git 提交**（.gitignore 已配置），放心填。

## 第 2 步：改主题前缀（1 分钟，强烈建议）

公共 Broker 上大家都用默认主题会互相看到数据。
打开 `components/MQTT_APP/mqtt_app.h`，把：

```c
#define MQTT_TOPIC_PREFIX    "swdscsc/attitude"
```

改成自己的，比如 `"swd0713/attitude"`（名字+日期，基本不会撞车）。
**改完记得把 `python/collector.py` 顶部的 TOPIC 同步改掉。**

## 第 3 步：编译烧录（10 分钟）

```bash
idf.py set-target esp32s3
idf.py build
idf.py -p COM口号 flash monitor
```

看到 monitor 里依次打印：

1. `WiFi 已连接，启动 MQTT`
2. `已连接 Broker，订阅命令主题: xxx/attitude/cmd`
3. `MQTT 已就绪，开始每 500ms 上报姿态`

就说明设备端跑通了。常见失败看下面「踩坑速查」。

## 第 4 步：验证数据在流动（3 分钟）

不想装 Python 环境的话，先用图形工具看：
下载 [MQTTX](https://mqttx.app/)（免费）→ 新建连接（Broker 填 `broker.emqx.io`，端口 1883）→
订阅 `你的前缀/attitude/data`，应该每 0.5 秒收到一条：
`{"ax":12.30,"ay":-3.10,"az":88.50}`

倾斜板子，数值变化 = 传感器数据真实上云了。**截图保存，这就是 README 里的证据图。**

## 第 5 步：Python 端采集入库（10 分钟）

```bash
cd python
python -m venv venv            # 第一次用先建虚拟环境
venv\Scripts\activate          # Windows
pip install -r requirements.txt
python collector.py
```

屏幕开始滚动数据说明链路全通。**让它跑 10 分钟**，期间把板子做几个动作：
放平 → 抬起 45° → 翻转 → 放平（这些动作会体现在曲线里，报告更好看）。
`Ctrl+C` 停止，数据在 `attitude.db` 里。

## 第 6 步：分析出图（5 分钟）

```bash
python analyze.py
```

得到 `report.png`（三轴时序图）和 `summary.csv`（统计表）。
检查一下：四个动作在图上应该是四段明显不同的曲线。

## 第 7 步：验证下行命令（5 分钟）

在 MQTTX 里向 `你的前缀/attitude/cmd` 发布消息：
- 发 `led_on` → 板载 LED 亮
- 发 `led_off` → 灭

**录一段 10 秒小视频或截图。** 至此上行（传感器→云）+ 下行（云→设备）双向链路全部验证。

## 第 8 步：更新 README 并提交（5 分钟）

1. 把 MQTTX 截图 / report.png 放进仓库 `docs/img/`，README 里的 `[ ]` 改成 `[x]`
2. 提交（在你自己的电脑上，正常 git 就能用）：

```bash
git init
git add .
git commit -m "feat: 上机验证完成，采集10分钟数据并产出分析报告"
```

3. 推送两种方式任选：
   - **网页上传**：GitHub 仓库页 → Add file → Upload files（最简单）
   - **命令行**：`git remote add origin https://github.com/swdscsc/esp32-attitude-iot-dashboard.git`
     然后 `git push -u origin main`（弹登录时用户名填 `swdscsc`，密码粘贴 PAT token）

## 踩坑速查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| monitor 卡在 `WiFi 已连接` 之前 | WiFi 密码错 / 用了 5G 频段热点 | ESP32-S3 只支持 2.4G，手机热点记得开 2.4G |
| `MQTT 已就绪` 不出现 | 公司/校园网封 1883 端口 | 换手机热点；或把 Broker 换成 `mqtt://test.mosquitto.org:1883` |
| MQTTX 收不到数据 | 主题前缀不一致 | 固件 `mqtt_app.h` 和 collector.py 的 TOPIC 逐字对比 |
| collector 报 rc=5 | 极少：公共 Broker 限流 | 等 1 分钟重连，或换 Mosquitto 公共实例 |
| LED 不亮 | 命令发错主题 | 确认发到 `.../cmd` 不是 `.../data`，payload 是 `led_on` 全小写 |
